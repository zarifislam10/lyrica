# Lyrica

Lyrica is an **educational karaoke app** that helps people learn languages by singing songs. The hypothesis: fans of K-pop, J-pop, Latin pop, etc. already enjoy singing along with lyrics they don't fully understand, and that moment is the hook for teaching pronunciation, meaning, and melody at the same time. Core experience: pick a song in a target language, sing along to a backing track with synchronized lyrics (original script + romanization + English meaning), get real-time pitch feedback plus post-line scoring on pitch, timing, and pronunciation.

Frontend is React 19 + TypeScript + Vite 8 + Tailwind CSS v4 at the repo root. Backend is Python 3 + FastAPI in `/backend`. Experimental speech-model work lives in `/ml` on branch `zarif-ml`.

## Product shape

Three connected modes. Users move through them per song.

- **LEARN.** Pick a lyric line. See the original script, romanization, and English meaning side by side. Hear ElevenLabs TTS speak the line at normal speed and slow speed. No scoring here.
- **PRACTICE.** Say the line without music. Record yourself and compare your recording to the TTS example. Pronunciation feedback when the probe supports it. Separate option to hum the melody first before adding words. Hum earns melody credit only, never pronunciation credit.
- **PERFORM.** Full karaoke. Backing track plays, lyrics scroll synchronized, target notes scroll as bars, your live mic pitch overlays on top. Countdown before each line. Per-section results, with a retry button for the weakest line.

Existing modes still ship for the Hack Knight demo:
- **Solo** and **Battle** (shipped via PR #5 and PR #12). Battle is one-device, two-player, higher Tune score wins. These will coexist with Perform and may eventually merge into it.

Three scores, shown separately and never combined into one number:
- **Pitch (Tune)** — how close your pitch is to the hand-typed target notes. Deterministic, lives in `src/domain/scoring.ts`.
- **Rhythm** — not yet split from Tune. Timing is folded into the Tune score today; splitting it out is planned.
- **Pronunciation (Words)** — experimental. Lives in `/ml` on branch `zarif-ml`. Until the probe validates on sung audio, the UI shows "Pronunciation — coming soon" with no number. **Never fake, stub, or guess a pronunciation number.**

Feedback matters more than the number. After each line, name the specific missed syllables and let the user hear the correct sound.

Rules that stay regardless of mode:
- **Target notes are hand-typed as semitones** in `src/data/songs.ts`. We do not try to extract the lead vocal melody from a full-mix backing track. Research (RMVPE and similar) shows this is hard even with trained models; a browser pitch detector cannot do it reliably. Hand-typing stays until we have a verified melody-extraction pipeline.
- **Never auto-tune the user's displayed pitch.** The point is that they learn to hit the note. Do not snap, smooth, or correct the overlay.
- Backing track is the music under the vocal. Does not contain the lead vocal. User sings the vocal.

## Content and licensing

Still can't ship copyrighted recordings or lyrics without licensing. Current options for growing the catalog:
1. **Public domain songs** (Happy Birthday today). Legal, boring.
2. **Original songs generated by us.** Suno or Udio for the music, ElevenLabs for the TTS reference. We transcribe lyrics ourselves and hand-type the melody. Legally clean, catalog can match K-pop / J-pop vibes.
3. **Licensed catalog** via a music rights service (Songtradr, Lickd, Musixmatch). Costs money, not realistic until there's a business.

Hard constraint until licensing is in place: no uploaded recordings of real artists, no scraped lyrics from label sites, no claimed real-artist attribution. Backing tracks that we didn't generate or license do not go in `public/songs/`.

Pronunciation of a non-native language (Korean, Japanese, Arabic, etc.) must be reviewed by a speaker of that language before we claim it's correct. Mark unreviewed syllable-to-note mappings `needs native speaker check` in `src/data/songs.ts`.

## Provider roles

- **ElevenLabs** — TTS for spoken pronunciation examples (powers "Hear it" and future Learn mode playback). Produces syllable timings. Speaks the Aux announcer line. Also offers forced-alignment; we have not yet integrated it.
- **Suno / Udio** — generate backing tracks for original songs. Not called from the app. We render tracks offline, review them, drop the instrumental into `public/songs/` and commit.
- **Gemini** — writes the announcer line and words a short coaching tip from the missed syllables our scorer identifies (`coaching` in `POST /round-result`). It never hears the take, never produces a score, never picks a winner, and never decides which syllables were missed.
- **Our code** decides scores and the winner.
- **TigerData** — leaderboard storage. **Only the backend talks to it.** No TigerData client in the frontend.
- **(Candidates under evaluation)** — Azure Pronunciation Assessment, Speechace, SpeechSuper for the Pronunciation score. Current `/ml` probe uses wav2vec2-xls-r-300m + DTW cosine similarity; validation on sung audio is pending. See `ml/README.md`.

## Mode roadmap (current direction)

Keep existing demo flow working. Add Learn/Practice/Perform incrementally, one at a time, as separate branches. Do not rip out Solo/Battle until Perform demonstrably replaces them.

1. **Perform v0.** Backing track plays while the user sings. Scrolling note bars already exist in `PitchLane`. Needs: synchronized lyrics overlay, backing track audio element on a shared timebase with the pitch sampler, countdown.
2. **Learn v0.** Line picker screen showing original + romanization + meaning + two TTS playback speeds. Reuses existing song data.
3. **Practice v0.** Mic recording of a spoken line (not sung), replay next to the TTS reference, pronunciation feedback once the probe is validated. Hum-only sub-mode uses only the Tune scorer.
4. **Longer songs.** Current song fixture is one 15-second line. Needs multi-section songs with per-section scoring and retry.
5. **Score split.** Separate Rhythm from Tune. New reducer field. New tests.

## Project structure

Canonical layout. Start with task-relevant files; follow imports only when necessary.

**Frontend**
- `src/main.tsx` — React entry; imports `src/index.css`, mounts `src/App.tsx` into `#root`.
- `src/App.tsx` — Top-level app shell and the SingScreen / RoundResultScreen. Routes between screens via the match reducer.
- `src/screens/` — Per-screen components too large to inline (SetupScreen, HandoverScreen, FinalScreen). Add new screens here when they exceed ~150 lines; otherwise keep them in `App.tsx`.
- `src/domain/` — Pure, framework-free logic. `scoring.ts` (Tune score), `scoring.test.ts`, `match.ts`, `match.test.ts`, `types.ts`.
- `src/data/songs.ts` — Static song content.
- `src/services/` — Browser-side side-effectful helpers: `microphone.ts`, `pitch.ts`, `audioSession.ts`, `melody.ts`.
- `src/index.css` — Global CSS + Tailwind v4 import.
- `index.html` — Vite shell. Real `<title>` and `<link rel="icon">` live here.
- `package.json`, `vite.config.ts`, `.mise.toml` — tooling.

**Backend**
- `backend/main.py` — FastAPI app; CORS and welcome endpoint; mounts routers.
- `backend/round_result.py` — `POST /round-result`: Gemini commentary + ElevenLabs TTS, Gemini coaching tips in parallel, 5s deadline, deterministic fallback. Saves a leaderboard row per player as a BackgroundTask when `optInToLeaderboard` is true.
- `backend/db.py` — asyncpg pool for TigerData. Reads `DATABASE_URL` once; never logs the URL. Returns None when the DB is unreachable.
- `backend/leaderboard.py` — `GET /leaderboard` and `GET /leaderboard/hardest`. Both return `[]` on error.
- `backend/migrate.py` — idempotent schema setup. Zarif runs this himself.
- `backend/generate_hear_it.py` — offline script: ElevenLabs TTS renders the "Hear it" clip for each song into `public/songs/<song id>.mp3`.
- `backend/.env.example` — placeholder keys. Real `.env` is gitignored.

**ML (experimental)**
- `ml/sound_match_test.py` — frozen wav2vec2-xls-r-300m + DTW cosine similarity probe. See `ml/README.md`.
- `ml/takes/` — voice recordings. **Never commit voice recordings.** Gitignored.
- `ml/.venv/` — gitignored.

## Code quality

- Double-quote strings that contain apostrophes, or escape in single quotes.
- Keep JSX balanced; default-export components.
- Prefer small, pure helpers in `src/domain/` over logic inside components.
- `src/domain/scoring.ts` is the Tune scorer. **Do not change its behavior or what its tests assert.** Mechanical renames in fixtures are allowed when types widen.
- `src/domain/match.ts` is the match reducer. Keep it pure. Any new state field needs reducer tests.
- No new runtime deps without a note explaining why.
- Secrets go in `backend/.env` only. Never commit real keys. Never return provider error bodies to the frontend.
