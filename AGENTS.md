# Lyrica

Lyrica is a **language learning app**. Users practice by singing lines in the language they're learning, solo or in a two-player battle. It is **not** a karaoke app. Never use the word "karaoke" in UI text.

Frontend is React 19 + TypeScript + Vite 8 + Tailwind CSS v4 at the repo root. Backend is Python 3 + FastAPI in `/backend`. Experimental speech-model work lives in `/ml` on branch `zarif-ml`.

## Product shape

- **Two modes, same scoring and same Aux rules in both.** Aux is the on-screen announcer (ElevenLabs voice over a Gemini-written line).
  - **Solo:** one player practices a line alone. Each take gets a Tune score (and Words when `/ml` ships) plus Aux's feedback on the missed syllables. Three lines, then an average at the end.
  - **Battle:** two players, one device, best of three. Players alternate turns; Aux calls each round.
- **One song to start: Happy Birthday**, in English, Korean, and Arabic (Modern Standard). Lyrics are hard-coded, not scraped.
- **Target notes are typed by hand as semitones.** Do not measure pitch from audio files. There are no "vocals-only" tracks for analysis.
- **Two scores, always shown separately.**
  - **Tune** — pitch shape and timing. Computed by `src/domain/scoring.ts`. Deterministic.
  - **Words** — pronunciation, from a pre-trained speech model. Experimental; lives in `/ml` on branch `zarif-ml` until its hum test passes. **Do not fake or stub a Words score in the UI.** Until the probe PASSes, reserve the layout slot and render "Words — coming soon" with no number.
- **Feedback matters more than the number.** After a turn, name the missed syllables and let the player hear the correct sound.

## Landing copy (exact)

- Headline: `Learn a language by singing it.`
- Subline: `Sing it. Say it right. Win the round.`

## Content rules

- No copyrighted songs or lyrics. No real artist names. No audio taken from other recordings. **All audio is generated by us** (ElevenLabs TTS).
- Happy Birthday is OK: lyrics are public domain and the audio is our own ElevenLabs render.
- Syllable-to-note mapping for Korean and Arabic must be marked `needs native speaker check` in `src/data/songs.ts` until a human speaker of that language confirms it.

## Provider roles

- **ElevenLabs** — speaks each line (powers "Hear it"), produces syllable timings, speaks the announcer line.
- **Gemini** — writes the announcer line **only**. It must never produce a score, pick a winner, or influence feedback.
- **Our code** decides scores and the winner.
- **Tiger Data** — leaderboard storage. **Only the backend talks to it.** No TigerData client in the frontend.

## Voice clone (stretch) rules

- Only with an **explicit OK from the player** in the UI (checkbox or confirm dialog, not an implicit opt-in).
- Used only to play the line back to that same player.
- **Deleted when the match ends.** Never stored. Never shared across players.

## Project Structure

Canonical layout. Start with task-relevant files; follow imports only when necessary.

**Frontend**
- `src/main.tsx` — React entry; imports `src/index.css`, mounts `src/App.tsx` into `#root`.
- `src/App.tsx` — Top-level app shell and the SingScreen / RoundResultScreen. Routes between screens via the match reducer.
- `src/screens/` — Per-screen components too large to inline (SetupScreen, HandoverScreen, FinalScreen). Add new screens here when they exceed ~150 lines; otherwise keep them in `App.tsx`.
- `src/domain/` — Pure, framework-free logic. `scoring.ts` (Tune score), `scoring.test.ts`, `match.ts`, `match.test.ts`, `types.ts`.
- `src/data/` — Static song content (`lines.ts` today; `songs.ts` once `laiba-songs` lands).
- `src/services/` — Browser-side side-effectful helpers: `microphone.ts`, `pitch.ts`, `audioSession.ts`.
- `src/index.css` — Global CSS + Tailwind v4 import.
- `index.html` — Vite shell. Real `<title>` and `<link rel="icon">` live here, not in `.figma/make/site.json` (that only applies to Figma Make's hosted preview).
- `package.json`, `vite.config.ts`, `.mise.toml` — tooling.

**Backend**
- `backend/main.py` — FastAPI app; CORS and welcome endpoint; mounts routers.
- `backend/round_result.py` — `POST /round-result`: Gemini commentary + ElevenLabs TTS with a shared 5s deadline and deterministic fallback.
- `backend/test_round_result.py` — unittest suite; mocks all provider calls.
- `backend/generate_hear_it.py` — offline script: ElevenLabs TTS speaks each song's line from `src/data/songs.ts` into `public/songs/<song id>.mp3` for "Hear it". Never called by the server. Tests in `backend/test_generate_hear_it.py` use a fake client.
- `backend/.env.example` — placeholder keys (`GEMINI_API_KEY`, `GEMINI_MODEL`, `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, `ELEVENLABS_MODEL_ID`, `ELEVENLABS_ROUND_MODEL_ID`, `ELEVENLABS_HEAR_IT_VOICE_ID`, `ELEVENLABS_HEAR_IT_MODEL_ID`, `DATABASE_URL`, `FRONTEND_ORIGINS`). Real `.env` is gitignored.

**ML (experimental)**
- `ml/sound_match_test.py` — frozen wav2vec2-xls-r-300m + DTW cosine similarity probe. See `ml/README.md`. Does not touch `src/` or `backend/`.
- `ml/takes/` — voice recordings. **Never commit voice recordings.** Gitignored.
- `ml/.venv/` — gitignored.

## Code quality

- Double-quote strings that contain apostrophes (`"We're here"`), or escape in single quotes. An unescaped `'` in a single-quoted string breaks the build.
- Keep JSX balanced; default-export components.
- Prefer small, pure helpers in `src/domain/` over logic inside components.
- `src/domain/scoring.ts` is the Tune scorer. **Do not change its behavior or what its tests assert.** Mechanical type renames in fixtures are allowed when types widen.
- `src/domain/match.ts` is the match reducer. Keep it pure. Any new state field needs reducer tests.
- No new runtime deps without a note explaining why. Dev deps are fine when justified.
- Secrets go in `backend/.env` only. Never commit real keys. Never return provider error bodies to the frontend.
